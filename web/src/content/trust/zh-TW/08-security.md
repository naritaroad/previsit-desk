## 帳號與工作階段

密碼用 Argon2id 雜湊保存，查無此人時也會做一次同樣成本的比對，避免用回應時間猜帳號。登入後發給 256 位元的隨機權杖，資料庫只存它的 SHA-256；cookie 設 HttpOnly、SameSite=Lax，正式環境加 Secure（C-29，依據：`backend/src/auth.rs`、`deploy/compose.prod.yaml` 的 `COOKIE_SECURE`）。每個來源十分鐘最多嘗試登入 10 次。使用者可以看到自己的登入裝置並逐一撤銷；管理員可以停用帳號、重設密碼、撤銷全部登入。<!-- verify: V-36 裝置清單、撤銷、停用後立即失效（backend/src/auth.rs） -->

沒有雙重驗證，也沒有忘記密碼的信件流程，因為系統不收電子郵件。忘記密碼只能由管理員重設成一次性密碼。<!-- verify: V-37 重設密碼發一次性密碼並強制更改 -->

## 角色與授權

角色有五種：病人、醫師、藥師、個案管理師、管理員。每個端點宣告需要哪一項權限，權限對照只有一張表，寫在 `backend/src/perm.rs`，管理站可以看整張矩陣。病人只讀得到自己的資料，醫事人員的讀取會留紀錄。管理員不含任何讀病人內容的權限。<!-- verify: V-38 每個端點的權限與越權測試 -->

個案管理師與醫師目前看得到診所裡所有病人，沒有限縮到自己負責的病人。真實診所要不要這樣開放，應由診所決定。

## 傳輸與網頁標頭

對外流量走 Cloudflare Tunnel，由 Cloudflare 終止 HTTPS；從 Cloudflare 到主機上的容器是加密通道，容器之間走主機內部網路。後端連接埠只綁在主機的 127.0.0.1，資料庫不對外開埠。每個回應帶 `Content-Security-Policy`，限制腳本與連線只能來自本站，行內腳本只准頁面裡那一段的雜湊；另有 `X-Content-Type-Options` 與 `Referrer-Policy`（C-30，依據：`backend/src/routes.rs` 的測試 `csp_allows_only_the_inline_script_that_is_in_the_page`）。樣式仍允許行內，HSTS 沒有由程式送出，是否由 Cloudflare 設定尚未確認。

## 額度與濫用

送訊息、建立問診、登入與其他動作各有頻率上限；模型呼叫有每日總量、每個來源、每次問診三種上限，失敗的呼叫也計數。來源位址只以加鹽雜湊存在記憶體，IPv6 以 /64 網段計，記錄上限 20,000 筆（C-32，依據：`backend/src/limits.rs`）。重啟之後計數歸零，多台主機之間也不共享；目前只有一台。

## 容器與主機

正式環境用 Docker Compose 跑三個容器：資料庫、後端、Cloudflare 通道。後端以唯讀檔案系統執行，移除所有 Linux capabilities，禁止提升權限，限制記憶體、CPU 與程序數，映像以非 root 使用者執行（C-31，依據：`deploy/compose.prod.yaml`、`Dockerfile`）。資料庫容器設了記憶體上限與禁止提權，但沒有唯讀檔案系統。主機與作者的另一個專案共用，兩邊用不同的 Compose 專案名稱與通道。

## 機密

模型金鑰、資料庫密碼與通道權杖放在主機的 `.env`，檔案權限限擁有者可讀，不進 git、不進映像。錯誤訊息寫進紀錄前會去除金鑰並截短。後端容器收到的通道權杖是空值，拿不到它。部署腳本發現必要的機密是空值或還是 `CHANGE_ME` 就停止。

## 稽核

管理動作、登入、續方決定寫進 `audit_log`，讀取病人資料寫進 `access_log`，兩張表都不存訊息內容、密碼或權杖。稽核寫入失敗時，動作不會撤回，只會留下錯誤紀錄；讀取紀錄寫入失敗時，資料不給讀。<!-- verify: V-39 續方決定、簽署、帳號變更都有 audit 列 -->

資料庫管理者可以修改這兩張表，沒有防竄改機制。

## 已知缺口

- 沒有雙重驗證、密碼外洩比對與登入異常通知。
- 沒有外部滲透測試。2026 年 11 月 25 日上線前做過一次內部審查，由開發流程中的另一個 AI 代理執行，讀程式碼並以重寫的規則比對，沒有對正式站攻擊。
- 資料庫檔案與備份沒有另外加密，依賴主機磁碟；備份清理靠人工。
- GitHub Pages 的工作流程沒有把第三方動作固定到雜湊；CI 的有。
- 提示詞注入只有樣式規則與資料標示，擋得住常見寫法，擋不住有心人。
- 後端只有一台，主機或 Cloudflare 故障時整個服務停擺。

## 怎麼通報

請依 [SECURITY.md](https://github.com/naritaroad/previsit-desk/blob/main/SECURITY.md) 用 GitHub 的私下通報功能，附上端點或檔案、重現步驟與影響。請勿在測試時讀取或修改其他訪客的資料，也不要發動大量流量。我們沒有獎金；處理時間寫在「事件通報與更正」。
