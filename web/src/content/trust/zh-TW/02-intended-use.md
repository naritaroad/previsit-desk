## 使用者與環境

病人端的使用者是能用繁體中文或英文打字、年滿 18 歲、病情不緊急的成人。年齡限制來自模型供應商：Gemini API 的條款要求使用者滿 18 歲，也不得把服務放進以未滿 18 歲者為對象的應用（C-03，[文獻 14][r14]）。系統目前沒有核對年齡，只在文件與註冊頁說明。<!-- verify: V-03 註冊與訪客試用畫面有年滿 18 歲的說明 -->

醫事端的使用者是醫師、藥師、個案管理師與管理員，各有自己的站台與權限。<!-- verify: V-04 四個站台與角色權限已上線（docs/v2/product.md §2–§3、backend/src/perm.rs） --> 使用環境是有網路的電腦或手機瀏覽器，純文字，沒有語音、影像或理學檢查。現階段只能用虛構資料做課堂展示。

## 適用情境

適合的是已經約好診、症狀穩定的門診前問診，常見主訴如咳嗽、腹痛、膝痛、血壓追蹤；以及想知道慢箋哪一天可以領下一次藥。續開申請適用於正在吃、病情穩定、藥物列在範圍內的慢性病用藥。<!-- verify: V-05 續開範圍依 data/seed/formulary.csv 執行 -->

## 不適用的用途

下列情況請不要使用，系統遇到也會盡量擋下或轉給人：

- 緊急症狀、自傷念頭、服藥過量或中毒。
- 未滿 18 歲者、孕產照護、替昏迷或無法表達的人描述病情。
- 要求新開處方、調整劑量、換藥、停藥，或任何管制藥品。
- 以系統結果作為診斷、請假、保險或法律文件。
- 輸入真實病歷、檢驗報告或他人個資。
- 真實的臨床作業。Gemini API 條款寫明服務不得用於臨床實務或提供醫療建議（[文獻 14][r14]），所以在更換模型方案以前，這套系統連在診所試辦都不行。

## 為什麼有的事做、有的事不做

世界衛生組織把大型多模態模型在健康領域的應用分成五類：診斷與臨床照護、病人自行使用、文書與行政、醫護教育、研究與藥物開發，並點出答案錯誤或偏誤、自動化偏誤、資安等風險（[文獻 13][r13]）。我們用這個分類檢查自己做的事。

### 衛教：在範圍內，但只轉述

系統從 `data/rag/health_education.zh-TW.md` 的章節找答案，每節有來源與查閱日，找不到就說手冊沒有。要做得更多，例如依個人病史給衛教，需要醫事人員審過的內容、定期更新的人，以及讀者真的讀懂的證據，目前一樣都沒有。

### 行政：在範圍內

預約、慢箋日期、申請狀態、待辦清單，對錯可以用規則與測試檢查。錯了會讓病人白跑一趟或斷藥，所以日期計算全部由程式負責，遇到管制藥、症狀變化、副作用一律轉人。

### 心理支持：不在範圍內

偵測到自傷念頭時，系統只給固定文字、1925 與 119，並停止對話（C-04，依據：`data/seed/red_flags.csv` 的 `suicide` 類、`backend/src/texts.rs`）。對話式的情緒支持需要臨床研究、督導與危機接手的人力。Google 的門診研究把以心理健康為主訴的病人排除在外（[文獻 1][r1]），我們沒有理由走得比它更前面。

### 分流：只做一小塊

系統只辨認少數應該立刻就醫的描述，命中就停。它不告訴病人「不急」「三天內看就好」，因為要說出這種話，得先在真實病人身上量過敏感度、特異度，以及漏掉的人後來怎麼了。醫師端的排序依轉交單緊急度與時間，不依模型判斷。

### 診療：不做

診斷、處方與劑量由醫師決定，調劑由藥師負責，《醫師法》第 11 條以親自診察為原則（[文獻 11][r11]）。AMIE 那類系統即使在研究裡提出可能的診斷，也有醫師即時監看，而且不把處置計畫給病人看（[文獻 1][r1]）。要把診療放進來，需要的是臨床試驗、主管機關許可與願意承擔責任的醫療機構，寫程式解決不了。

### 若要擴大範圍

下表整理每一類還缺什麼。

| 類別 | 目前 | 若要擴大，缺的證據 | 若要擴大，誰要負責 |
|---|---|---|---|
| 衛教 | 轉述有來源的章節 | 讀者理解度、內容更新頻率 | 審閱內容的醫事人員 |
| 行政 | 規則計算、轉人 | 與健保實際核付的比對 | 診所與藥局 |
| 心理支持 | 固定文字與專線 | 臨床研究、危機處理成效 | 心理或精神專業團隊 |
| 分流 | 少數紅旗，命中即停 | 真實病人的漏報率與後果 | 醫療機構與具名醫師 |
| 診療 | 不做 | 臨床試驗與上市許可 | 醫師、製造方、主管機關 |
