# PreVisit Desk v2 產品規格

2026-11-25。取代 v1 的 `docs/product/product-spec.md`（v1 的紅旗、越界、輸出檢查、慢箋四種結果等規則原樣沿用，見 `docs/engineering/backend-spec.md` §4–§8、§13）。HTTP 形狀見 `docs/v2/contract.md`。

## 1. 為什麼重做

v1 是一頁聊天加一個醫師清單：沒有病人帳號、沒有病歷脈絡、續方只有試算、醫師只能標「已審閱」、安全頁是六張卡片。v2 是一個**四種角色、有紀錄、可接續**的診所服務。

## 2. 角色與站台（介面分開，各有自己的外框與導覽）

| 站台 | 路徑 | 角色 | 主要工作 |
|---|---|---|---|
| 公開站 | `/` | 訪客 | 認識服務、信任中心、登入、免註冊試用 |
| 病人站 | `/app` | `patient`（含訪客沙盒） | 預問診、用藥與續方、掛號、健康檔案、訊息、隱私 |
| 醫師站 | `/clinic` | `physician`、`coordinator` | 待審清單、審閱台、續方審核、病人管理、訊息接手、門診表 |
| 藥局站 | `/pharmacy` | `pharmacist` | 領藥與續方調劑佇列、核對、退回醫師 |
| 管理站 | `/admin` | `admin` | 帳號與權限、AI 設定與預算、監督指標、稽核、規則與評測、資料保留 |

預設帳號五個：`naritaroad`（admin）＋四名預設用戶 `dr_demo`（陳柏宇 醫師）、`rph_demo`（吳思穎 藥師）、`cm_demo`（許雅雯 個案管理師）、`patient_demo`（林秀琴）。密碼全部在 `.env`。全部是虛構人物。

**訪客沙盒**：公開站按「用示範病人試用」會建立一個只屬於這個瀏覽器的病人帳號，帶入一位虛構病人的健康檔案、用藥與慢箋。資料與其他訪客隔離；可以設定帳號密碼把它變成正式帳號（原資料保留）。

## 3. 權限

`Permission` 是程式裡的列舉，角色→權限是一張表，管理站可看整張矩陣；個別帳號可停用、改角色、撤銷工作階段、重設密碼。每個端點宣告需要的權限；沒有權限回 403。醫事人員**讀取病人資料會寫 `access_log`**，病人在「隱私」頁看得到誰、何時、看了什麼。

## 4. 病人站

1. **首頁**：下一個約診、進行中的預問診（可接續）、用藥倒數（哪一張慢箋幾天後可領）、進行中的申請、未讀訊息。
2. **預問診**：清單（搜尋、釘選、封存）與對話。可綁定約診。AI 先帶入健康檔案已知的病史、用藥、過敏，請病人確認而不是重問。摘要病人可逐欄修改再送出。紅旗流程同 v1，任何模式都先跑。
3. **用藥與續方**：用藥清單、每張慢箋的領藥進度（第幾次、下一次可領窗口的時間軸）、兩種申請：
   - **領藥預約（refill）**：慢箋第 2、3 次領藥。程式檢核窗口→選藥局與取藥時間→藥師核對→備藥完成→已領取。
   - **續開申請（renewal）**：慢箋快用完或已用完。流程見 §5。
4. **約診**：看醫師時段、預約、取消、報到前完成預問診。
5. **訊息**：和醫療團隊的對話（AI 轉真人後在同一串）。
6. **健康檔案**：病史、用藥、過敏、量測（血壓、血糖、體重，可畫趨勢）。病人自填標「自述」，診所紀錄標「診所」。
7. **隱私與資料**：同意書版本、誰看過我的資料、登入裝置、匯出 JSON、刪除帳號。

## 5. 續開申請（參考 Doctronic 猶他州協議的結構，改成台灣可行的樣子）

在台灣，處方必須由醫師開立。本系統的續開申請**不開處方**：它把醫師續開前需要的資訊備齊，由醫師決定；醫師同意後，正式處方仍由醫師在看診或通訊診察中開立。

步驟（精靈，每一步自動存檔，可跨裝置接續）：
1. 選擇要續的藥（來自慢箋；可一次多項）。每項先顯示範圍：可申請／需醫師個別評估／不接受線上申請（管制藥、針劑等），附理由。
2. 身分與用藥確認：核對藥名、每日怎麼吃（照處方紀錄顯示，病人只回答「跟我現在吃的一樣嗎」）、上次領藥。
3. 安全問題：一般題＋該藥類的題目（`data/seed/renewal_protocols.json`）。
4. 近期數據：血壓、血糖、檢驗日期（可帶入健康檔案量測）。
5. 藥局與聯絡偏好。
6. 檢視與同意：清楚寫「醫師會審閱每一件」「不會自動核准」「預計處理時間」。
7. 送出→狀態頁（時間軸）。

**協定引擎**（純 Rust、確定性）對每一項輸出 `ready`／`review`／`in_person`／`urgent`／`excluded`，附觸發的規則與來源。`urgent` 立即顯示紅旗卡並開緊急單，不進一般佇列。引擎結果只決定醫師看到什麼、排在哪裡，**永遠不等於核准**。

**監督階段**（管理站可看、不可在介面上自行跳階）：第 1 階段＝醫師審 100%（目前）；第 2、3 階段只在說明中描述需要的條件（每藥類滿 250 件且一致率達門檻、倫理與主管機關核准），本系統不實作自動核准。

**狀態機**：`draft → submitted → in_review → (more_info ⇄ in_review) → approved | declined | visit_required`；`approved → at_pharmacy → ready → dispensed`；任何未完成狀態可 `cancelled`；`in_review` 超過 SLA 標逾時。領藥預約：`draft → submitted → at_pharmacy → ready → dispensed`，藥師可 `returned`（退回並說明）或轉醫師。所有轉移寫 `rx_events`，以 `revision` 防止同時覆寫。

醫師決定每一項：`approve`（照原處方續）、`decline`、`visit_required`、`more_info`（附問題）。**不能在系統內改劑量或換藥**；需要改就選 `visit_required`。決定與引擎結果的一致率進監督儀表板。

## 6. 醫師站（參考 AMIE 延伸研究的「醫師監督台」概念：AI 只整理病史，判斷留給醫師）

- **工作清單**：緊急、逾時、今日門診、待審、等病人回覆；篩選、指派給我、批次。
- **審閱台**：左：病人脈絡（檔案、用藥、過去預問診）；中：AI 整理的主觀資料（S）與自述量測（O），每一句可點回原對話；右：醫師自己寫的評估與計畫（A、P）、給病人的話。自動存草稿、版本、簽署後鎖定，修正要開「補記」。AI 不填 A、P。
- **續方審核**：引擎結果、規則與來源、答案、量測趨勢、逐項決定、要求補充、與病人訊息。
- **接手對話**：轉交單→接手→AI 暫停、真人回覆→結案或交回 AI。
- **病人管理**：清單、標籤、追蹤狀態、內部備註、負責醫師／個管師、聯絡紀錄、整合時間軸。個管師可做除簽署與續方決定以外的事。

## 7. 管理站

總覽（量、成本、紅旗、SLA、模型狀態）、帳號（新增、停用、改角色、重設密碼、撤銷登入）、角色權限矩陣、AI 設定（模型、備援、思考等級、每日上限、每月預算、緊急停用開關）、監督指標（引擎與醫師一致率、各狀態處理時間、退回率）、執行紀錄（每個 run 的工具、用量、失敗）、稽核紀錄、規則檢視（紅旗、越界、慢箋、續方協定、藥品範圍）、評測結果、資料保留與示範資料重設。

## 8. 狀態持久化

| 需求 | 設計 |
|---|---|
| 斷線、重整、換裝置接續對話 | 事件寫 `visit_events`（單調 `seq`）；回合在伺服器背景執行，與連線無關；`GET /visits/{id}/stream?after=seq` 重播後接即時 |
| 重送不重複 | `client_id`（訊息）與 `Idempotency-Key`（建立類請求）唯一 |
| 伺服器重啟 | 啟動時把 `running` 的 run 標成 `interrupted`，病人看得到「上一則沒有完成，重試」 |
| 草稿不遺失 | `drafts`（每帳號、每 scope）自動存，帶 `revision`；本機 IndexedDB 先寫、背景同步；衝突回 409 與伺服器版本，介面讓人選 |
| 多分頁 | BroadcastChannel 同步；同一回合只有一個在跑 |
| 離線 | 送出佇列，恢復連線後依序重送 |
| 精靈與表單 | 草稿在伺服器（`rx_requests.status='draft'`），步驟、答案都保存 |
| 偏好 | 語言、主題、字級、側欄、篩選存帳號 `preferences` |
| 併發編輯 | 筆記、申請、檔案都有 `revision`，寫入帶 `If-Match` |
| 保留與刪除 | 訪客沙盒與 visit 依 `RETENTION_DAYS`；示範資料可重設；刪除帳號立即清除 |

## 9. 信任中心（取代安全頁）

`/trust` 是有目錄、有版本與負責人的**敘述式文件**，分頁：總覽、預定用途、AI 怎麼運作與不做什麼、臨床安全（危害分析與控制、紅旗、輸出檢查）、人為監督（階段、醫師責任）、續方安全（範圍、排除、協定、來源）、隱私與資料、資安、評測與證據（題庫、方法、結果、限制）、事件通報與更正、法規對應、名詞與參考文獻、變更紀錄。寫法像 NHS 數位臨床安全文件與正式產品的說明，不用卡片牆；每個可驗證的說法都指到程式、資料或公開來源；沒做的事直接寫沒做。

## 10. 不變的界線

v1 的六條不變。另加：續方引擎不核准、系統不改處方、醫師的 A/P 不由 AI 產生、讀取病人資料一律留紀錄、所有人物與資料皆為虛構、不是醫療器材。
